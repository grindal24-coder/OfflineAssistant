# Offline AI Voice Assistant for Android

Локальный голосовой ассистент без облачных ИИ-сервисов. Реализация по ТЗ,
двухуровневая LLM-схема: **Llama 3.2 1B** (быстрые команды) + **Llama 3.2 3B**
(сложные запросы, подключается по требованию). Подробности схемы —
`app/src/main/java/com/offlineassistant/ai/ModelTier.kt`.

## Статус проекта

Это **скелет с рабочей архитектурой**, а не готовое к использованию
приложение. Компилируется и ставится структура классов, Android API вызовы
(звонки, SMS, таймеры, напоминания, музыка, поиск, чтение уведомлений) —
реализованы полностью. Два места остаются TODO, потому что требуют внешних
SDK/ключей, которые не имеет смысла подделывать:

1. **Wake-word детектор** (`wakeword/PorcupineWakeWordDetector.kt`) — требует
   Picovoice AccessKey и обучения кастомной фразы "Эй Ассистент" через их
   консоль (либо замены на TFLite/Vosk — интерфейс `WakeWordDetector.kt` это
   позволяет без изменений в остальном коде).
2. **Полностью офлайн STT** (`speech/WhisperCppRecognizer.kt`) — нужен ещё один
   JNI-мост к whisper.cpp по аналогии с LlamaBridge. Сейчас как временный
   fallback используется системный `AndroidSpeechRecognizer`
   (`speech/AndroidSpeechToText.kt`), который на многих прошивках ходит в
   облако Google — это временно и **не** соответствует офлайн-требованию п.17 ТЗ,
   замени на whisper.cpp перед релизом.

**JNI-генерация текста** (`app/src/main/cpp/native-lib.cpp`, функция `generate`)
теперь реализована полностью (токенизация -> decode-цикл -> семплинг ->
детокенизация -> остановка по EOG-токену или по завершённому JSON). Написана
под API llama.cpp образца 2024-2025 — **не гарантированно скомпилируется
без сверки с той версией submodule'а, которую ты подключишь**, у llama.cpp
API между релизами меняется. Если сборка native-части упадёт с ошибками
про отсутствующие символы — см. подробный комментарий в начале
`native-lib.cpp`, раздел "ФУНКЦИИ, ЧУВСТВИТЕЛЬНЫЕ К ВЕРСИИ" — там же совет
закрепить submodule на конкретном релизном теге вместо `main`, чтобы API не
уезжал сам по себе при обновлении.

Всё остальное — Room-база, обработчики команд, permissions, foreground-сервис,
CommandRouter, JSON-контракт intent'ов — рабочий код, а не заглушки.

## Сборка

### 1. llama.cpp подключается автоматически — тебе делать ничего не нужно

Раньше здесь была инструкция про `git submodule add` — убрано, потому что
для сборки без Android Studio/локального git это лишний барьер. Вместо
этого `.github/workflows/build-apk.yml` сам клонирует llama.cpp прямо на
сервере GitHub при каждой сборке — в шаге "Клонировать llama.cpp".

Версия закреплена на теге **v0.3.0** (первый стабильный номерной релиз
llama.cpp, август 2026) — сознательно не на `main`, чтобы API, под который
написан `app/src/main/cpp/native-lib.cpp`, не менялся из-под кода сам по
себе. Если когда-нибудь понадобится более свежее ядро — поменяй тег в
workflow-файле, но тогда возможно придётся сверить сигнатуры функций в
`native-lib.cpp` заново (см. комментарий "ФУНКЦИИ, ЧУВСТВИТЕЛЬНЫЕ К ВЕРСИИ"
в начале файла).

Если всё же захочешь собирать локально в Android Studio (не через CI) —
тогда действительно нужно один раз получить исходники llama.cpp на диск:

```bash
git clone --branch v0.3.0 --depth 1 https://github.com/ggml-org/llama.cpp ai/llama.cpp
```

(просто скачай так же, как это делает CI — необязательно именно через
submodule, обычная папка с исходниками тоже подойдёт, `.gitignore` уже
настроен её не коммитить).

### 2. Открыть в Android Studio

Открой корень `OfflineAssistant/` в Android Studio (Iguana+). Studio сам
сгенерирует `gradle-wrapper.jar` при первом синке — если попросит,
разреши "Create Gradle wrapper".

NDK и CMake ставятся через SDK Manager -> SDK Tools, если ещё не стоят
(нужны для сборки нативной части, см. `app/build.gradle.kts`).

### 3. Модели

См. `ai/models/README.md` — куда класть GGUF-файлы 1B и 3B моделей.

### 4. Поиск с синтезом ответа (опционально)

ASK-intent (см. `commands/WebAnswerHandler.kt`) — это то, что делает ассистента
похожим на Gemini/Perplexity: не просто открывает браузер, а сам ищет и
озвучивает ответ. Работает так: поиск через API -> сниппеты -> локальная 3B
модель синтезирует короткий ответ на их основе (RAG). В сеть уходит только
сам поисковый запрос, весь синтез текста остаётся на устройстве.

**Без настройки** — работает "из коробки" через бесключевой DuckDuckGo Instant
Answer API, но он покрывает только справочные факты (определения, известные
сущности), не актуальные новости.

**Для нормального качества** — заведи бесплатный ключ Brave Search API
(https://brave.com/search/api/, есть бесплатный тир с лимитом запросов/месяц)
и положи его в `local.properties` (в корне проекта, файл НЕ в git):

```properties
BRAVE_SEARCH_API_KEY=твой_ключ_здесь
```

Gradle сам подхватит его в `BuildConfig.BRAVE_SEARCH_API_KEY` при следующей
сборке — ничего в коде менять не нужно.

### 5. Собрать APK

```bash
./gradlew assembleRelease
```

или через Android Studio: Build -> Build Bundle(s)/APK(s) -> Build APK(s).

Выход: `app/build/outputs/apk/release/app-release.apk`.

## Известные ограничения (важно прочитать перед тестом на реальном устройстве)

- **Перехват кнопок громкости** (`ui/ButtonAccessibilityService.kt`, п.14
  ТЗ вариант 1) может не срабатывать стабильно в фоне на Android 11+ и особенно
  на кастомных прошивках (MIUI и т.п.) из-за агрессивного энергосбережения.
  Если не заработает — переходи на вариант 2 (`ROLE_ASSISTANT` /
  `VoiceInteractionService`), закомментированная заготовка есть в
  `AndroidManifest.xml`.
- **Доступ к уведомлениям** (`NotificationReaderService`) нельзя запросить
  программно диалогом — пользователь должен вручную включить его в
  Настройки -> Специальные возможности -> Доступ к уведомлениям. Стоит
  добавить в UI кнопку, открывающую `Settings.ACTION_NOTIFICATION_LISTENER_SETTINGS`.
- **Function calling у 1B/3B без grammar constraints** может изредка выдавать
  невалидный JSON — `IntentJson.parse` терпимый к мусору вокруг JSON, но
  для продакшена стоит добавить GBNF-грамматику в llama.cpp сэмплер
  (гарантирует валидный JSON на выходе, см. TODO в `native-lib.cpp`).
- **Porcupine лицензия**: бесплатен только для личного использования с лимитом
  активаций — проверь актуальные условия перед публикацией приложения.

## Структура проекта (соответствует п.16 ТЗ)

```
OfflineAssistant/
├── app/
│   ├── src/main/java/com/offlineassistant/
│   │   ├── ai/          — LlamaBridge (JNI), LlamaEngine (1B/3B оркестрация)
│   │   ├── speech/       — STT (Android SpeechRecognizer + whisper.cpp заготовка)
│   │   ├── wakeword/    — детектор "Эй" + foreground-сервис
│   │   ├── commands/    — CommandRouter + обработчики (звонки/SMS/таймеры/...)
│   │   ├── database/    — Room: контакты, история команд, напоминания
│   │   └── ui/          — MainActivity, AccessibilityService для кнопок
│   └── src/main/cpp/    — CMakeLists.txt + native-lib.cpp (JNI мост к llama.cpp)
├── ai/
│   ├── llama.cpp/       — git submodule (не в репо, см. шаг 1 сборки)
│   └── models/          — сюда кладутся GGUF файлы (не в git)
└── README.md
```

## Что было пересмотрено по итогам ревью ТЗ

Список изменений за это ревью, с обоснованием — что реально важно, а что
намеренно отклонено (полная оценка была дана в переписке, коротко здесь):

- **Wake word "Эй" → "Эй Ассистент"** — короткое слово даёт много ложных
  срабатываний (обычная речь, телевизор). См. `strings.xml`,
  `PorcupineWakeWordDetector.kt`.
- **Confidence-based роутинг 1B→3B** — раньше решение было бинарным
  (`intent == UNKNOWN` или нет). Теперь 1B обязана возвращать поле
  `confidence` (0.0-1.0), и есть список `CRITICAL_INTENTS` (CALL, SMS) —
  для них эскалация в 3B происходит ВСЕГДА, даже при высоком confidence, т.к.
  цена ошибки высока (звонок/SMS не тому контакту). См. `LlamaEngine.kt`,
  `Intent.kt`.
- **Contact Resolver с уточнением** — раньше ненайденный алиас контакта
  просто возвращал ошибку. Теперь `ContactResolver` открывает системный
  picker контактов (`ContactRegistrationActivity`), пользователь выбирает
  контакт один раз, дальше "Позвони маме" резолвится мгновенно из Room.
- **Кнопки громкости: окно 300мс вместо строгой одновременности** — раньше
  требовалось буквально одновременное нажатие обеих кнопок, что физически
  почти недостижимо. См. `ButtonAccessibilityService.kt`.
- **ASK-intent с поиском и синтезом ответа** — новый сценарий: "какая
  погода", "кто выиграл вчера" и т.п. теперь не просто открывают браузер
  (это по-прежнему SEARCH), а получают голосовой ответ, синтезированный
  локальной 3B моделью на основе результатов поиска. См. раздел выше
  "Поиск с синтезом ответа" и `commands/WebAnswerHandler.kt`.

**Сознательно НЕ реализовано** (см. обоснование в комментариях к коду):
- Принудительная выгрузка 1B на время работы 3B — не нужна при 12GB RAM
  целевого устройства, добавила бы задержку без пользы.
- Таблица "Users" в Room — приложение однопользовательское (личный
  ассистент на одном телефоне), лишняя сущность.
- Прямая интеграция с Weather API — противоречила бы офлайн-принципу
  сильнее, чем ASK через поиск; ASK и так закрывает этот сценарий.
- Полный кастомный UI с анимированным "AI Core" вместо чат-интерфейса —
  концепт хороший, но это отдельная UI/UX задача, не техническая правка.
- Автозапуск для Xiaomi/MIUI — это не код, а инструкция пользователю
  (Настройки -> Автозапуск -> разрешить для приложения), добавь вручную
  при тестировании на Xiaomi-устройстве.

## Дальнейшие шаги после первого запуска

Собери и установи APK, проверь:
1. Компилируется ли нативная часть на твоём NDK/CMake (самое вероятное место
   проблем на первом запуске — версии CMake/NDK, пути к submodule).
2. Просит ли приложение все permissions при первом запуске.
3. Держится ли WakeWordService в фоне (Settings -> Battery -> отключить
   оптимизацию батареи для приложения, иначе Android может убивать сервис).

Дай знать, что выдаст сборка — разберём ошибки по месту.
